# literature-rag-assistant — 基于 RAG 的文献问答助手

## 角色定位

你是"基于 RAG 的文献问答助手"模块的开发者。核心职责是：接收用户科研问题，从本地文献库检索最相关的内容，结合 LLM（DeepSeek-V4-Pro）生成准确、有据可查的回答。

## 基本原则

1. **本地优先** — 所有回答必须基于本地文献库和向量数据库中的内容。如果本地库中没有相关信息，应明确告知用户，而非编造答案。
2. **引用必标注** — 每条引用信息后面标注来源（第一作者, 年份, DOI 或 arXiv ID）。方便用户查阅原文。
3. **区分事实与推测** — LLM 的推理性总结与文献原文的事实性陈述应明确区分。
4. **中文回答** — 回答使用中文，专业术语可保留英文并在首次出现时标注中文含义。

## 系统架构

```
用户提问 → 查询改写 → 向量检索 → 重排序 → 上下文组装 → LLM 生成 → 引用标注 → 回答输出
              ↑                        ↓
         本地文献库 (SQLite)      向量数据库 (ChromaDB)
```

### 步骤 1：查询改写 (Query Rewriting)

将用户的自然语言问题改写为更适合检索的形式：

- 中文问题 → 中英文混合关键词提取
- 口语化表达 → 学术术语映射（如"AI 看病" → "medical image diagnosis artificial intelligence"）
- 多子问题 → 拆分为多个独立查询

```python
def rewrite_query(user_question: str, llm_client) -> list[str]:
    """将用户问题改写为 2-5 个检索查询"""
    # 使用 LLM 做查询改写，输出为关键词列表
    ...
```

### 步骤 2：向量检索 (Vector Retrieval)

- 使用与入库时相同的嵌入模型将查询向量化。
- 在 ChromaDB 中检索 top-K 最相似文档块（默认 K=20）。
- 支持混合检索：向量相似度 + 关键词匹配（BM25）结合。

### 步骤 3：重排序 (Reranking)

对检索到的文档块进行精细排序：

- Cross-encoder 重排序模型：`bge-reranker-v2-m3` 或 `Cohere Rerank API`
- 考虑到引用新鲜度：年份越新的论文给予小幅度加分。
- 考虑到课题组论文：`is_group_paper=1` 的论文轻微加权。

### 步骤 4：上下文组装 (Context Assembly)

将重排后的 top-N 文档块（默认 N=8）组装为 LLM 的上下文：

```
【文献 1】标题：... | 作者：... | 年份：... | DOI：...
摘要：...
相关段落：...

【文献 2】...
```

注意控制上下文总长度不超过 LLM 上下文窗口的 60%（留 40% 给对话和生成）。

### 步骤 5：LLM 生成 (Answer Generation)

系统提示词概要：

```
你是科研文献问答助手。基于以下文献内容回答用户问题。
- 如果文献内容不足以回答，请明确说明。
- 引用文献时标注 (作者, 年份)。
- 使用中文回答，专业术语首次出现时标注英文。
- 如果需要推测或总结，请注明"基于以上文献推测"。

文献内容：
{context}

用户问题：{question}
```

### 步骤 6：引用标注与输出格式化

最终回答格式示例：

```markdown
## 回答

在医学图像分割领域，U-Net 架构在 2015 年提出后成为主流基线 (Ronneberger, 2015, arXiv:1505.04597)。

### 参考文献
1. Ronneberger et al. (2015). U-Net: Convolutional Networks for Biomedical Image Segmentation. arXiv:1505.04597. [本地库已收录]
2. ...
```

## 回答质量要求

- **准确性**：回答必须与文献原文一致，不得凭空编造数据、实验结果或引用。
- **覆盖度**：尽量覆盖不同的观点和方法，不偏袒某一篇论文。
- **时效性**：如果用户关心最新进展，优先检索和引用近期论文。
- **自知之明**：如果本地库中确实没有相关信息，如实告知："本地文献库中暂未找到相关论文，建议用检索模块搜索以下关键词：...，或者上传相关 PDF。"

## 本地库未命中时的处理

如果向量检索返回的相似度均低于阈值（如 cosine < 0.5）：

1. 告知用户："本地文献库中未找到与问题高度相关的论文。"
2. 建议用户使用 `paper-search-and-oa-download` skill 先检索下载相关论文。
3. 在用户同意后，可调用检索 API 提供在线检索结果摘要（不使用 RAG，仅作为检索建议）。

## 对话管理

- 支持多轮对话上下文：用户追问时，不应丢失前一轮已引用的文献。
- `/new` 命令重置会话，清空对话历史。
- `/sources` 命令列出当前回答引用的所有文献。

## 性能优化

- 向量检索缓存：相同查询的检索结果缓存 30 分钟。
- 文中引用预加载：高频引用的论文全量信息缓存在内存中。
- 流式输出：长回答使用 Server-Sent Events (SSE) 流式输出 token。

## 评估

定期对回答进行人工抽查评估：
- 是否有事实错误
- 引用是否正确
- 回答是否完整覆盖用户问题
